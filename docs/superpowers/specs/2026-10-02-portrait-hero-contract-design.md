# 人物主视觉首帧正式契约设计（v1 历史稿）

> 本文已由 [人像首帧正式契约 v2.0](2026-10-03-portrait-first-frame-contract-v2.md) 取代。保留本文件仅用于记录早期两人样例的设计与实现背景；新的配方、阈值和迁移工作以 v2.0 为准。

**日期：** 2026-10-02
**状态：** 已由 v2.0 取代（历史证据）
**范围：** 为现有黑金长图 Skill 增加 `portrait-ensemble` 首帧配方；本次先以两位人物为验收样例。

## 1. 问题与目标

此前的试稿把人像先临时处理、再作为普通图片拼到像素画布中。它既没有锁定抠像资产，也没有用可测几何约束人物关系，因此会出现白边、头部尺度不一致、身体露出比例不一致、人物与说明文字脱节；即使画面颜色接近黑金，也不是正式 Skill 产物。

本设计的目标是把“人物 + 解释文字 + 黑金首帧”做成一个可复用、可编辑、可验证的 L01 变体。最终产物仍必须是已有正式流程中的 `plan.md → render.html → poster.html → final.png → layout-manifest.json → verify-case-layout.py`，而不是单张位图示意稿。

本设计不将原图矩形裁切作为人物版式方法；人物视觉必须来自已验收的透明 RGBA 资产。原图矩形只可作为资产审计源，不能直接进入首帧。

## 2. 配方身份与适用范围

### L01-P01｜Portrait Ensemble（人物组首帧）

- **适用输入：** 2–4 位用户确认可用的人物；每人具有姓名、身份/角色说明与一份可验收的透明资产。
- **叙事顺序：** 主题 → 副标/解释 → 人物组主视觉 → 逐人姓名与身份 → 元信息。
- **默认关系：** 两人或多人组成一个居中的共同主视觉；至少一人前景、至少一人后景。三人及以上时，几何中心人物是视觉焦点，必须位于最前层；层级只来自身体区域的有限前后关系，不能来自遮住另一人的头或脸。
- **不适用：** 缺少逐人说明文字；无法提供合法、干净透明资产；人物数超过 4；或内容实际需要导师名录/人物墙时。后两种分别走 L13，不伪装成首帧主视觉。

### 黑金母版不可变约束

- 主画布为 `1080px` 宽、`#10100F`；面板/过渡为 `#181816`；主标题 `#F0ECE2`；单一强调金 `#CCAA77`；辅助文字 `#94918A`。
- 首帧为第一阅读区，标记 `data-hero-cover`，且使用 L01 的标题先行顺序。标题/副标仍在 `x=112–968, y=160–640` 的安全区内。
- 人物承载面必须是唯一 `data-hero-surface`，从首帧中下段延展至画布边缘，并唯一包含 `data-hero`。它是黑金版式的一部分，不能用独立白底照片或卡通背景替代。
- 金色只用于必要的信息信号（眉题、规则线、少量重点），不把整页正文、人名和装饰同时染金。

## 3. 资产阶段：先锁定，后编排

人物分割是独立资产阶段，不是排版阶段的隐式步骤。

### 3.1 输入和输出

每位人物都登记：

```text
id / source_path / source_sha256 / usage_permission
alpha_asset_path / alpha_asset_sha256 / alpha_provider / provider_version
head_top / eye_line / chin / shoulder_below / visible_silhouette_bbox
asset_qa_status / human_review_status
```

- `alpha_provider` 必须是获准、可离线复现、非生成式的前景分割/抠像实现；它只能改变 alpha 与边缘去污染，不能重绘人、脸、发型、衣物、姿态或背景中的人物细节。
- 去污染必须基于相邻背景色/alpha 的边缘颜色校正；它不是用生成式补画遮掉白边。
- 禁止 alpha 腐蚀、手绘轮廓收缩、固定高度容器裁切、`clip-path` 或任何会删掉发顶、发丝、耳部、眼镜、肩线等原有完整部位的处理。完整透明轮廓必须原样进入编排阶段。
- 资产生成完即冻结 hash。编排/渲染步骤只能引用冻结的 `alpha_asset_path`，不得重新分割、重新阈值、换模型或改用原图；任何替换都必须回到资产阶段并重新验收。
- 真人只能使用用户确认的原始肖像及其非生成式 alpha 派生物，禁止生成式改脸或修复。卡通资产也必须保持原始角色形态。

### 3.2 资产验收门槛（阻断发布）

每个资产须在深色 `#10100F` 与浅色 `#F0ECE2` 背景上导出等尺寸审阅图，且通过：

1. 四周透明、无源图矩形底色；
2. 头发、眼镜、耳部、手指、衣物边缘无连续白/灰/背景色晕边；
3. 不存在未抠除的大块背景、洞孔、锯齿、轮廓断裂或主体被切掉；
4. 真人身份、卡通角色的原有外观没有被模型重绘；
5. 所有可见水印、版权标识均按来源许可处理：不得静默擦除。若水印无法合法保留且进入发布画面，则该资产为 `blocked`，不能通过正式首帧验收。

浏览器渲染前，`asset-qa.json` 及两张背景审阅图必须存在。未通过的人物不能以“待语义蒙版”“临时阈值”“来源裁切”身份进入 `data-hero`。

## 4. 人物组几何合同

所有度量由浏览器对最终 `poster.html` 的渲染结果计算；不是源图片像素，也不是手填 manifest。

### 4.1 人物锚点

每个 `data-hero-subject` 必须拥有已登记且可见的：

```text
head_bbox = [x, y, w, h]        # 发顶到下巴的视觉头部框
eye_line_y                       # 双眼中线；歪头可按平均眼高
shoulder_below_y                 # 该人“肩部以下”的统一露出锚点
visible_bbox                     # 实际可见透明轮廓的包围框
caption_bbox                     # 该人物的姓名 + 身份说明组
z_index                          # 人物组内的前后景次序
```

这些锚点在资产审核时标注，在最终页面中通过同一 CSS 变换投影、实测和写入 manifest。缩放基准是 `head_bbox.h`，不是源图片宽高，也不是人物完整身体的高度。

### 4.2 尺度、露出和居中

- 同一人物组内，任意两人的最终 `head_bbox.h` 相对差不得超过 **3%**。这是焦段不同的人像仍保持等量级人物存在感的依据。
- 两人的眼线垂直差不得超过较小头高的 **8%**；人物有明确仰俯/倾斜姿态时，Plan 要登记原因，但仍不得借此造成一高一低的面部层级。
- 配方选择一个共同 `exposure_anchor=shoulder-below`。所有人物在该锚点处结束/淡出，最终从发顶到可见下缘的规范化高度相对差不得超过 **5%**。因此全身照也只呈现到与半身照相同的“肩部以下”比例，不按原照片露出更多身体。
- 人像的唯一允许融入方式是 `lower-fade-only`：渐隐起点不得早于 `shoulder_below_y`，渐隐过渡区不得短于 **240px**；它只能让下半身逐步融入 `#10100F`，不得作用在头部或两侧完整轮廓。
- 人物组合并后的可见轮廓包围框中心相对画布中心的误差不得超过 **24px**。标题可左对齐，人物组仍须作为整体居中，不能随其中一张原图偏到边上。
- 人物组及其逐人说明必须完全位于内容安全区 `x=112–968`，不越过出血线。三人组的整体轮廓应呈横向矩形：宽度不得小于高度；不能以单个长条人物或零散头像代替一个完整组。
- 至少两个不同的 `z_index` 必须存在；前后关系只用于制造纵深，不能把两人排成无关系的并列证件照。
- 三人及以上时，离画布水平中心最近的头部必须拥有该组最高 `z_index`。这给出焦点，但不允许增大其头部尺度来制造主讲层级。

### 4.3 遮挡限制

- 任意两人的 `head_bbox` 不得相交；额头、头发、面部、五官、眼镜均不得被另一位人物遮挡。
- 身体轮廓允许交叠的区域必须完全位于双方 `shoulder_below_y` 之下。
- 任意一对的人体交叠面积，不得大于较小一方可见身体（不含头部）面积的 **1/3**。
- 人物不得遮挡另一人的姓名、身份说明、全局标题、副标、元信息或必要规则线。

## 5. 人物与文字是一套配方

### 5.1 全局文案组

全局 `data-hero-copy` 由眉题、主标题和副标组成，位于人物组之前。其底边到人物组可见顶部间距为 **64–144px**。这保留现有 L01 的“标题先于主视觉”阅读顺序；人物不是悬空装饰。

### 5.2 逐人解释组

每个 `data-hero-subject` 必须有且仅有一个 `data-hero-subject-caption`，其中包含：

```text
姓名（primary） + 身份/角色说明（secondary）
```

- Caption 是人物组的直接成员，不得挪到首帧底部、另一个容器或与其他人物共用一块说明。
- 并列人物配方中，caption 位于人物可见轮廓下方的独立下侧槽，其顶边距对应人物可见下缘 **16–48px**；横向对齐到该人的头部中心或肩线。它不能跨越到另一个人的说明槽，也不能压在人像上方。
- Caption 与对应 `head_bbox` 的横向投影必须相交或相距不超过 **0.5 个头宽**，以避免人名像无归属的页面标签。
- 姓名与身份说明必须维持同一人物组内一致的字号、字重、行数预算和视觉层级；人名不是装饰性底部浮标。两组 caption 之间及 caption 与全局 copy 之间不得碰撞。
- 文案必须使用正式的 `data-layout-role`、浏览器实测换行和字号规则；任何溢出、单字孤儿行、跨人物误归属都使该首帧失败。

## 6. 所需语义标记与 manifest 扩展

首帧 HTML 在现有 hero 标记上增加：

```html
<section data-reading-zone="cover" data-hero-cover data-contract="L01-P01">
  <div data-hero-copy>…</div>
  <div data-hero-surface>
    <div data-hero="portrait-ensemble" data-hero-ensemble>
      <figure data-hero-subject="wizard" data-depth="foreground">…</figure>
      <figure data-hero-subject="tingting" data-depth="background">…</figure>
    </div>
  </div>
</section>
```

每个 figure 的人物图片、可见轮廓测量层、caption 都须具备稳定属性；不能从渲染后的 PNG 反推语义。`export_layout_manifest.py` 将为 `portrait-ensemble` 输出：

```json
{
  "hero": {
    "strategy": "portrait-ensemble",
    "copy_anchor_bottom": 0,
    "copy_group_height": 0,
    "group": {"visible_bbox": [0,0,0,0], "center_offset_x": 0, "depth_order": []},
    "subjects": [{
      "id": "", "asset_sha256": "", "asset_qa": "passed",
      "head_bbox": [0,0,0,0], "eye_line_y": 0,
      "shoulder_below_y": 0, "visible_bbox": [0,0,0,0],
      "body_visible_bbox": [0,0,0,0], "caption_bbox": [0,0,0,0],
      "z_index": 0
    }],
    "pairwise_overlap": [{"a": "", "b": "", "head_intersection": 0, "body_overlap_ratio": 0}]
  }
}
```

数字必须由 Chromium 实测；asset hash 与 QA 状态由被引用的 `asset-qa.json` 验证，而不是写入 HTML 后自行声明。

## 7. 验证和失败语义

`verify-case-layout.py` 增加 `portrait-ensemble` 分支，拒绝以下任一情况：

1. 缺失唯一 hero surface、唯一 hero、任一人物/逐人 caption 或正式 L01 标记；
2. 人数不在 2–4、资产 hash/QA 记录缺失、任何资产状态不是 `passed`；
3. 头高、眼线、露出比例、组居中与安全区、中心焦点层级、头部遮挡或身体遮挡未达到第 4 节阈值；
4. 人物或 caption 与全局 copy/彼此发生碰撞，或 caption 不满足归属距离；
5. 未通过现有字体、画布、便携 HTML、浏览器来源、文字溢出、PNG 像素和人工视觉审阅检查。

人像透明边缘 QA 不由单一像素阈值取代：机器验证证明来源与资产锁定，深/浅背景审阅图与人工视觉核验负责识别头发、玻璃、半透明发丝等边缘质量。正式验收报告必须列出两者。

## 8. 本次首帧案例的输入边界

本轮只用用户给出的两位测试人物：

- 真人：`巫师｜跨界 : 组队共创者.png`
- 卡通：`婷婷｜超级个体 : 独立设计师 : AI工作坊.png`

两者都先进入独立 alpha QA，之后才可进入首帧。卡通来源当前带有 `豆包AI生成` 水印；正式产物不得静默清除它。若它会落在可见区且无法按授权保留，应更换为无水印、获准来源后才可发布。这个规则同样适用于未来所有人物素材。

## 9. 实施边界与迁移顺序

1. 增加资产 QA 数据格式、深浅背景审阅输出与可批准的非生成式分割适配器；
2. 扩展 `export_layout_manifest.py`，让浏览器输出人物组实测锚点和 caption；
3. 扩展 `verify-case-layout.py` 与对应测试，验证本契约每个硬限制；
4. 在 `references/layout-contracts.md` 和 `references/layout-recipes.md` 登记 L01-P01，更新 `SKILL.md` 的人物首帧路由；
5. 用两人案例走完整正式管线，只有所有自动校验及人工 alpha 审阅通过才输出首帧 PNG。

不会把当前任何像素试稿、临时阈值抠图或生成式试验图升级为正式案例；它们只能作为失败证据，不可进入资产清单或发布包。

## 10. 验收定义

当且仅当下列条件同时成立，才称为“按黑金 Skill 正式契约输出的人物首帧”：

- 产物有经确认的内容计划、可编辑 render 源、可移交的 `poster.html`、浏览器导出的 PNG、manifest、render proof 与校验报告；
- 人物来自被冻结且通过深/浅背景人工审阅的透明资产；
- 人物组及每位说明文字满足本契约所有实测几何规则；
- 整个首帧满足既有黑金 L01 结构、色彩、字体、可读性与便携交付规则；
- 人工最终检查确认背景融合自然、人物无白边/灰边、文字归属清楚、没有未处理水印或来源风险。
