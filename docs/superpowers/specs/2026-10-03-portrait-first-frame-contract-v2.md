**日期：** 2026-10-03

**范围：** 只升级“人像首帧契约”；本文件不修改黑金长图 Skill 本体、日常路由或既有 `SKILL.md`。

## 1. 契约目标

人像首帧不是“先抠图，再把几张 PNG 放进海报”。它是一个由以下五层共同成立的版式系统：

1. 可复现、非生成式的透明人像资产；
2. 以头部视觉尺度为基准的人物映射；
3. 人物数量与叙事关系对应的固定配方；
4. 与人物直接绑定的姓名和解释文字；
5. 黑金首帧的标题、背景、网格与连续融合。

本契约把已经人工验收的四套配方固化为 `P01–P04`。编号沿用训练过程中的既有编号，不按人物数量重新排序，避免破坏案例与后续迁移记录。

## 3. 黑金首帧共同 Token

### 3.1 画布与内容轴

| Token | 值 |
|---|---|
| 画布宽度 | `1080px` |
| 画布底色 | `#10100F` |
| 主内容左边界 | `x=112` |
| 主内容右边界 | `x=968` |
| 主内容宽度 | `856px` |
| 主文字 | `#F0ECE2` |
| 主题金 | `#CCAA77` |
| 辅助文字 | `#94918A` |
| 最小下缘渐隐长度 | `240px` |

人物组、逐人说明和主标题均以同一主内容轴为基准。人物可以通过透明轮廓接近边界，但人物组、标签和说明文字不得越过 `x=112–968`。

### 3.2 首帧信息关系

- 眉题独立置顶，字级明显小于标题；眉题与标题之间保留显著距离。
- 主标题与副标题是近邻信息组；副标题只补充新信息，不复述眉题或标题。
- 标题、副标题、人物组按“标题先读、人物后读”的顺序排列，不能留下无意义的大空场。
- 背景主视觉必须是满幅连续表面，向人物上方和下方延展；不得裁成一个独立矩形卡片。
- 背景可以由 ImageGen 生成，但人物本体不得由 ImageGen 改脸、重绘、扩图或重生。

## 4. 人像资产合同

### 4.1 分割路线

- 真人与卡通均使用可复现的非生成式前景分割；当前已验证路线为本地 BiRefNet 类透明分割。
- 分割步骤只允许改变 alpha 和边缘去污染，不得改变人物身份、五官、发型、衣物、姿态或比例。
- 每张透明资产必须冻结 `source_sha256`、`alpha_asset_sha256`、模型/版本和 QA 状态。
- 排版阶段只能引用已冻结的 alpha；不得在不同配方中临时换模型、重新阈值或退回原图矩形裁切。

### 4.2 边缘 QA

每张透明资产必须在 `#10100F` 与 `#F0ECE2` 两种背景上复核：

1. 不存在连续白边、灰边、原背景残留或源图矩形；
2. 发丝、眼镜、耳部、手指、衣物边缘连续；
3. 头顶、脸、下巴、肩部、手臂、手和其他原本完整部位不得被切掉；
4. 水印和来源限制必须登记，不能静默擦除；
5. 任何一项失败，人物资产状态为 `blocked`，不能进入正式首帧。

### 4.3 下缘融合

- 主要躯干必须先以实体形态呈现，不能从胸口或肩部提前变虚。
- 唯一允许的融合模式是 `lower-fade-only`；渐隐只发生在身体最下缘。
- 渐隐起点不得早于肩部以下的实体躯干，过渡长度不得小于 `240px`。
- 渐隐终点必须在源图真实 alpha/画面边界之前完全透明，禁止露出源图底边、手臂平口或水平切线。
- 完整肢体优先于统一底线：如果统一底线会切断手臂，应调整人物位置或提前在更低处渐隐，而不是裁掉肢体。

## 5. 通用人物映射合同

### 5.1 尺度基准

- 多人组按最终可见 `head_bbox` 排版，不按源图宽度、高度、焦段或原始留白排版。
- 同一组的人物头部视觉高度差默认不超过 `3%`；`P04` 允许取 `max(4%, 8px)`，以适应上下层透视与不同媒介。
- 头部相等不等于身体图片等宽。人物容器、缩放和位置必须独立求解。
- 单人配方以肩部视觉宽度和主标题视觉宽度建立关系，不使用源图宽度作为尺度依据。

### 5.2 人物组关系

- 人物组是一个整体主视觉，整体水平中心相对画布中心误差不超过 `24px`。
- 多人组的最左和最右可见轮廓与主内容区建立边界关系；不得因某张原图留白导致整组偏移。
- `P01` / `P03` 的 `head_bbox` 不得相交；`P04` 因前后层交错允许头发外框接触，但实测 `face_bbox` 不得相交，五官和眼镜始终不得被遮挡。
- 身体交叠只能发生在肩部以下；任意一对身体交叠面积不得超过较小一方可见身体面积的 `1/3`。
- 人物数量减少时必须相应放大人物，不能沿用多人组的小尺度导致首帧空洞。
- 人物数量增加时优先建立前后层级与连续体量，不能缩成一排零散头像。

### 5.3 人物与文字绑定

- 每位人物必须有且只有一个姓名 + 身份说明组；文字是人物配方的一部分，不是后补浮标。
- 同一张海报内，所有人物说明必须使用同一种对齐逻辑：全部左对齐、全部居中或全部顶对齐，禁止混用。
- 姓名使用主题金或主题金标签；身份说明使用暖白或暖灰，并保证落在人物上方时仍有足够对比。
- 文字不得遮挡脸部、五官或关键手势；人物也不得遮挡姓名与身份说明。
- 人物、姓名与身份必须能通过空间距离明确配对，不能让读者猜测归属。

## 6. 固定配方

### 6.1 `P02`｜单人焦点

**适用：** 一位主讲人、导师或唯一人物主视觉。

- 人物是首帧唯一人物锚点，整体在主内容轴内居中。
- 人物从头部完整露出至腹部附近；肩部和主要躯干保持实体，下缘再渐隐。
- 人物肩部可见宽度与主标题渲染宽度建立近似关系，目标误差不超过 `5%`；不得超过 `x=112–968`。
- 姓名与身份放在人物头部右侧的安静区，并与头部形成一个信息组；不得压脸。
- 人物较少时优先放大人物，禁止保留多人配方的缩小尺度。

### 6.2 `P03`｜双人等权

**适用：** 两位同权人物共同解释主题。

- 两人头部等尺度，眼线与露出比例接近；不得通过一大一小制造无依据主次。
- 两人可见轮廓整体居中，最左与最右贴近主内容区左右边界。
- 默认不发生身体交叠；若素材姿态造成轻微交叠，仍须遵守 `1/3` 上限且不遮肩线。
- 两组姓名与身份放在人物下方，各自绑定头部轴或肩部轴。
- 两组文字必须采用完全相同的对齐方式、字号、间距和基线；已验收案例使用居中对齐。

### 6.3 `P01`｜三人并列

**适用：** 三位同权人物组成横向人物组，同时需要一个视觉焦点稳定构图。

- 三颗头部等尺度，三人的身体露出终点一致，人物组呈横向矩形体量。
- 中间人物位于最前层并成为视觉焦点；焦点来自层级，不来自增大头部。
- 脸部不交叠；身体遮挡不超过 `1/3`。
- 三位人物的姓名与身份置于人物下方，三组文字共用同一基线、对齐方式和层级。
- 人物组的可见左右边界对齐 `x=112–968`，并作为整体居中。

### 6.4 `P04`｜四人两层分组

**适用：** 四位人物需要形成一个饱满主视觉，而不是平铺人物墙。

- 使用上下两层、左右两列的斜向交错关系；上层在后，下层在前。
- 四颗头部保持近似等尺度；前景人物不得放大头部制造层级。
- 后排人物至少完整露出头部、颈部、双肩和一段实体躯干；前排不得遮住后排肩线。
- 前排与后排具有相近的组内密度。若前排已发生躯干交叠，后排两颗头部之间不得留下明显更大的空洞。
- 四位人物共同形成连续、紧凑的菱形或横向矩形体量；可见人物组宽度不得小于主内容宽度的 `82%`。
- 左侧人物姓名标签在外侧左方，右侧人物标签在外侧右方；身份说明位于标签朝组内的一侧。
- 前排人物的姓名与身份优先放在各自肩部外侧，标签中心大致对应肩线高度。
- 右侧人物可以向右展开以平衡重量，但标签和说明外沿不得超过 `x=968`。

## 7. `P04` 竖排文字与标签合同

- 姓名使用 `#CCAA77` 直角矩形标签，文字使用 `#10100F`。
- 标签与身份说明必须顶对齐；标签矩形顶部与相邻说明首行顶部误差不超过 `4px`。
- 同一人物组的标签宽度、内边距、姓名字级、说明字级和标签—说明间距保持一致。
- 竖排文本中的数字、英文及中英混合词组必须作为不可拆分的横排 token，例如 `AI`、`12`、`B端`；禁止拆成逐字符竖排。
- 身份说明与浅色衣物重叠时必须增加受控对比（暗色阴影、局部暗场或调整位置），但不能增加新的卡片式矩形破坏人物融合。

## 8. 背景合同

- 背景是从标题下方向人物上下延展的连续 `[data-hero-surface]`，不是人物后面的独立方块。
- 主视觉重点位于人物头部和人物组中心之间，不能全部堆在人物上方。
- 抽象背景可包含炭黑、暖灰、少量黄铜光汇和低对比网格；背景不能抢人物脸部。
- 背景图案的下缘应延伸到人物下缘之后，再自然进入黑色画布；不能与人物在同一水平线突然结束。
- 不允许出现独立蒙版矩形、水平硬边、局部不透明叠片或压在人像上方的错误层级。

## 9. 语义标记与 Manifest v4

正式人物首帧使用：

```html
<div
  data-hero="portrait-ensemble"
  data-portrait-recipe="P04"
  data-hero-ensemble>
  <figure
    data-hero-subject="wizard"
    data-depth="foreground"
    data-z-index="4">…</figure>
</div>
```

`P02` 仍使用同一 `portrait-ensemble` 策略，但人物数为 1；配方差异由 `data-portrait-recipe` 决定，不再用不同 hero strategy 绕过校验。

Manifest 在既有字段上增加：

```json
{
  "hero": {
    "strategy": "portrait-ensemble",
    "recipe_id": "P04",
    "title_bbox": [112, 210, 856, 300],
    "group": {
      "visible_bbox": [0, 0, 0, 0],
      "center_offset_x": 0
    },
    "subjects": [{
      "id": "wizard",
      "depth": "foreground",
      "head_bbox": [0, 0, 0, 0],
      "face_bbox": [0, 0, 0, 0],
      "shoulder_below_y": 0,
      "shoulder_bbox": [0, 0, 0, 0],
      "visible_bbox": [0, 0, 0, 0],
      "body_visible_bbox": [0, 0, 0, 0],
      "caption_bbox": [0, 0, 0, 0],
      "label_bbox": [0, 0, 0, 0],
      "role_bbox": [0, 0, 0, 0],
      "caption_alignment": "top",
      "caption_orientation": "vertical",
      "required_protected_tokens": ["AI"],
      "protected_tokens": ["AI"]
    }]
  }
}
```

所有几何字段必须由最终 `poster.html` 的 Chromium DOM 实测产生；不得手填 manifest 冒充通过。

## 10. 自动校验与人工验收边界

### 10.1 自动硬校验

- `recipe_id` 必须为 `P01–P04`，且人数分别为 `3 / 1 / 2 / 4`。
- 人物资产 hash、QA 记录、分割路径和渐隐参数完整。
- 人物组与逐人 `visible_bbox` 均位于 `x=112–968`；肩线和实体身体测量框必须属于该人物的可见框，姓名与身份测量框必须属于该人物的 caption。
- 人物组居中、头部尺度、P01/P03 头部相交、P04 面部相交、身体交叠和文字碰撞满足本契约。
- `P01` 必须是中心前景、两侧后景；`P03` caption 顶部误差不超过 `4px`，露出比例误差不超过 `5%`。
- `P02` 的人物可见宽度与实测标题宽度误差不超过 `5%`。
- `P01` 中间人物为最高层；`P04` 同时包含前景与后景，且后排肩线未被前排覆盖。
- 同一组 caption 的对齐方式一致；`P04` 标签与说明顶对齐。
- 竖排保护 token 通过 `required_protected_tokens` 声明，并在 DOM 中以 `[data-no-split-token]` 单一节点实测匹配。
- `poster.html`、manifest、render proof 和 `final.png` 来自同一浏览器母版。

### 10.2 必须人工确认

- 真人/卡通边缘是否仍有白边、灰边或背景污染；
- 人物视觉重量是否一致，尤其是不同焦段、姿态和媒介；
- `P04` 前后两层的组内密度是否平衡；
- 人物下缘是否自然融入，而不是“技术上透明、视觉上硬切”；
- 抽象背景是否成熟、连续并真正服务人物；
- 姓名、身份与人物的归属是否一眼明确。

自动通过不能替代这些人工判断；最终状态仍为 `agent-checked / human-review-needed`，直到用户明确确认。

## 11. 阻断条件

出现以下任一情况，契约验收失败：

1. 使用原图矩形裁切代替透明人物；
2. 使用 ImageGen 重绘、扩写或替换人物；
3. 白边、源背景、蒙版矩形或水平硬切可见；
4. 原本完整的头发、肩部、手臂、手或其他部位被切掉；
5. 多人按原图大小排版而非按头部视觉尺度映射；
6. 脸部相互遮挡，或身体遮挡超过 `1/3`；
7. 后排人物只剩头部，没有双肩和实体躯干；
8. 同组人物说明混用不同对齐方式；
9. 标签与说明未顶对齐，或数字/英文被逐字符拆开；
10. 人物组、标签或说明越过 `x=112–968`；
11. 背景被裁成独立方块，或图案在人物下缘之前突然结束；
12. 仅修改 PNG，没有同步更新可编辑 HTML、manifest 和验证证明。
