# 内容规划规则

## 0. 生产前判断顺序 · 待验证

生产前检查不是新增一套内容规则，而是将本文件、`layout-recipes.md`、`layout-contracts.md`、风格 / 主题文件中的既有判断按先后收束进案例 `plan.md`。必须按下列顺序完成；前一步未通过，不能用后面的版式或生图来掩盖问题。

| 顺序 | 先判断什么 | 通过条件 | 不通过时回到哪里 |
|---|---|---|---|
| 1. 输入可用性 | 原文、必须保留信息、事实状态、可用素材与限制是否已盘点 | 每条源信息有去处；待核对事实已标记；素材缺口与人物 / 品牌限制明确 | 向用户确认会改变事实、受众或目标的歧义；否则整理输入 |
| 2. 整图叙事 | 全文最主要的阅读关系是什么 | 已选一个 `Rxx` 主配方，且比例、帧数与它服务的阅读节奏一致 | 重组信息模块或增帧；不以缩字解决 |
| 3. 阅读区结构 | 每一段为什么这样讲，内容内部是什么真实关系 | 每段完成“问题 → 理解 / 结论 → 依据 → Lxx / 视觉 → 下一段”；没有伪造流程、对照或证据 | 回到信息关系判断、补依据或改为观点表达 |
| 4. 资产可用性 | 每个阅读区需要什么画面，它能否安全地承担这个任务 | 已定义资产角色、事实用途、原始比例 / 裁切锚点、主体避让、文字叠图与 alpha 路径 | 改选 `Lxx`、调整资产关系、补素材或取消不必要装饰 |
| 5. 视觉系统 | 所选风格、主题与案例状态能否承载上述内容 | 只选一个风格和其下一个主题；主视觉、容器、色彩、字体和接触影路径无冲突 | 改选可用组合，或把案例留在受控验证，不把未验证规则当作基线 |
| 6. 放行 | 以上决定能否真正开始生产 | 所有阻塞项已关闭，Plan 状态为 `approved-for-production` | 状态为 `input-blocked` 或 `preflight-blocked`，写明阻塞项与下一步 |

- “向用户确认”只用于不同答案会实质改变事实、受众、目标、叙事或版式的情况；不要把每个阅读区的问题转成问卷。
- 这是生产前的顺序，不代替出图后的 `daily-self-check.md`。后者负责核对最终图是否兑现本次决定。
- 本规则要在至少一个高密度 / 人像或证据型案例，以及一个主张型案例中验证，确认它能提前暴露真实阻塞项，而不是把 Plan 变成重复填写。

## 1. 文案先拆为信息模块

每份文案先标记：

- `claim`：核心主张或标题；
- `context`：副标题、对象、背景；
- `explain`：解释、并列观点或证据；
- `proof`：数据、案例、资源或视觉证据；
- `benefit`：权益、结果或覆盖范围；
- `action`：价格、时间、二维码占位或行动信息。

先确认模块的关系，再安排画面。不可把所有模块等权塞进首帧。

## 1.1 文本角色与关系识别

先标记文本角色，再写出可观察的关系：并列、明确先后、进阶、比较、层级、真实证据、权益/交付、行动或无结构化关系。文本角色不直接决定 `Lxx`；完整候选与禁用判断以 `layout-recipes.md` 的“配方选择索引”为唯一真源。

- 例如“12 周课程安排”可归为 `proof`，但其真实关系是周次顺序，应评估 `L15`；“4 项服务交付”属于 `benefit`，应评估 `L14`，不能只因数量是 4 就默认 `L04`。
- 若不存在真实结构，记录“无结构化关系”，再使用可读的正文或平级结构；不得为了丰富画面虚构时间、阶段、因果、机构或箭头。

## 2. 帧数与比例

| 文案形态 | 默认决定 |
|---|---|
| 单一主张 + 少量说明 | 2 张 `9:16` |
| 主张 + 2–4 个解释模块 + 行动 | 3 张 `9:16` |
| 有多组证据、流程、案例或并列清单 | 4 张或更多 `9:16` |
| 横向截图、表格、对照是核心证据 | 整个项目选择 `3:4` |

- 文字过多时优先增加帧、阅读区或总高度，不得降低字号下限、压缩、删减或改写用户提供的源文案。
- 同一长图不混用 `9:16` 和 `3:4` 主帧。

## 3. 每个阅读区必须先写“为什么这样讲”的链路 · 待验证

信息骨架、R 配方和 L 契约分别解决“内容是什么形状”“整图如何推进”“这一段如何落位”。在选择视觉资产前，必须将它们连接为一条阅读区链路：

```text
读者此刻需要理解的问题
→ 本段要建立的理解 / 结论
→ 用于支撑理解的源信息或可见依据
→ 因此选择的 Lxx 结构与视觉资产关系
→ 看完后由下一阅读区继续回答什么
```

### 阅读区签名

每个阅读区把上述链路压缩为一条可比对的**阅读区签名**。它不新增另一套叙事，也不要求每段都有图片；用途是让 Agent 判断不同案例是否只换了文案，或某个视觉资产是否真的服务本段。

```text
reader_question：读者此刻需要确认什么
claim：本段要建立的理解 / 结论
evidence_role：文字解释 / 已确认事实或数据 / 真实来源资产 / 语义主视觉 / 程序化结构 / 阅读承诺 / 行动引导
visual_relation：主体、文字、证据或结构如何共同解释 claim；没有视觉时写“纯文字结构”
Lxx：由真实信息关系选择的契约
transition_to_next：下一阅读区继续回答什么
```

- `evidence_role` 不要求把每段伪装为事实证明；首帧主张与末段行动可分别写“阅读承诺”和“行动引导”。
- `visual_relation` 只描述内容关系、文字避让与融入方式，不引入电商品类、产品锁或“景别”字段。
- 相邻阅读区的签名不得只更换标题或颜色：至少要在读者问题、结论、证据职责、视觉关系或 `Lxx` 中有一项源于真实内容的变化。

- 这是 Plan 中的内部设计判断，不是逐段向用户追问的问卷；根据用户文案、明确受众、任务目标和已提供素材推断。只有不同判断会显著改变整图叙事、事实用途或版式选择时，才请求用户确认。
- “可见依据”可以是用户提供的事实、数据、案例、人物身份、照片、截图、步骤关系或直接解释内容的语义视觉；首帧主张、情绪建立和收束行动可声明为“阅读承诺 / 行动引导”，不伪装为事实证据。
- 若本段提出可核对的事实、数字、比较、人物能力或案例结论，依据必须来自已确认输入；没有依据时，拆弱为观点表达、标为待确认或回到内容阶段补充，不能用氛围图假装证明。
- 图像、插画和装饰只服务本段链路中的依据或理解；不能解释该链路的氛围物件不进入资产清单。
- 当并列分条主要由文字构成、读者难以快速区分条目时，可为每一条附一个小 icon。icon 必须从该条的关键词提取，和标签一一对应，只承担识别而不补充未提供事实；优先使用许可明确、同一视觉语言的图标库。只有图标库无法表达且区分收益明确时，才可用一次 ImageGen 生成无文字、透明背景的同组 icon 资产。加号、方框、菱形等基础几何形不视为语义 icon，除非源文案本身表达该形状；没有明确区分收益时不添加。
- 本规则需通过至少一个人物 / 案例 / 数据型阅读区和一个非证据主导阅读区验证：确认它能帮助选择结构与资产，而不是把每段都机械伪装成“事实证明”。

## 4. 每次必须先写整图节奏矩阵

```text
帧 / 内容任务 / 信息骨架 / 主视觉位置 / 文字动作 / 容器语法 / 信号色职责 / 密度
```

三帧常见节奏是“建立 → 展开 → 收束”，但不是固定版式。每一帧必须有独立阅读任务，行动信息只在收束帧出现。

每帧还必须先选一个信息骨架：`主张 / 问题 / 清单 / 对比 / 流程 / 地图 / 行动`，并在 Plan 的“阅读区链路”中写明它回答的问题、要建立的理解、可见依据、Lxx / 视觉选择原因与下一段衔接。主视觉、插画和装饰必须直接解释该骨架中的关系；不能说明关系的氛围物件不进入资产清单。

若文案出现重复单元，必须先判断其真实关系，不能默认平铺成同一种卡片：

| 文案信号 | 优先结构 |
|---|---|
| 权益、交付、价值与可选价格 | 权益 / 价值清单 |
| 日期、周次、课次或有明确先后 | 时间轴 / 日程 |
| 阶段、能力进阶或从 A 到 B 的路径 | 阶段路径 |
| 真实去向、客户、合作方或机构标识 | 标识 / 去向矩阵 |
| 核心、外围、支持层或资源流向 | 层级 / 关系图 |

相邻阅读区不得使用同一版式契约；整张图中任一契约最多使用两次。该约束在写 Plan 时先检查，而不是等成图后再靠换色修补。

## 5. 项目 Plan 的最低字段

新任务直接复制 `daily-plan-template.md` 为项目目录内的 `plan.md`，再填写以下字段：

```text
项目名称
输入文案
生产前检查结论、阻塞项与下一步
比例与帧数，以及原因
Rxx 主配方与选择原因
风格与主题
主视觉分支与主要容器语法
整图节奏矩阵
每帧信息骨架
阅读区链路（问题 → 理解 / 结论 → 依据 → Lxx / 视觉选择 → 下一段）
每个阅读区的版式契约序列、配方使用次数与边距 Token
每个阅读区的阅读区签名
文字后置清单
局部视觉资产清单
单图验证预算（首帧主视觉、完整渲染与局部检查次数）
拼接与手机端检查项
```
