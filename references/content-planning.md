# 内容规划规则

本文件把输入长文拆为“原文理解”和“营销表达”两层。它们完成后才选择配方、资产和版式。

## 1. 生产前判断顺序

| 顺序 | 判断 | 通过条件 | 未通过时 |
|---|---|---|---|
| 1 | 输入可用性 | 仅盘点当前对话输入，全部可追溯 | `input-blocked`，补输入或澄清 |
| 2 | 内容分析 | 主张、解释、证据、利益、行动与真实关系已标记 | 回原文整理，不编造关系 |
| 3 | 营销确认 | 已产出展示文案与来源映射 | `awaiting-copy-confirmation` |
| 4 | 素材登记与首帧决定 | 确认稿同轮询问的人像/二维码已登记；`portrait_hero_decision` 已记录 | 等待本轮回复或使用已声明缺失状态 |
| 5 | 整图叙事 | 已选 R 配方和阅读区序列 | 重组内容，不缩字 |
| 6 | 阅读区与资产 | 每区有契约、结构节奏与资产职责 | 改结构、补素材或删无意义装饰 |
| 7 | 放行 | 所有生产阻塞关闭；QR 缺失仅允许占位稿，不允许发布 | `approved-for-production` 或待补输入 |

用户只进行一次文案确认。确认稿末尾必须附：“是否有希望使用的导师/嘉宾人像，以及报名二维码可一并上传？如有，请现在一并提供。”用户确认并上传后写入白名单与 Plan；不得随后重复索取二维码或询问是否把人像放在首帧。

`portrait_hero_decision` 是内部入口：默认 `theme-imagegen`，导师/嘉宾人像进入中段讲师信息；只有用户主动明确要求人像担任首帧主视觉时才为 `mentor-portrait-by-request`。R 配方、阅读区、L 契约与视觉方向由 Agent 根据真实信息关系决定，不做用户问卷。

## 2. 原文理解与营销确认

保留完整 `source_copy`，为每段标记 `claim / context / explain / proof / benefit / action`，并建立 `fact_locks`。人名、机构、日期、时间、地点、金额、数量、课次、权益、CTA、二维码动作、经历、成果和一切可验证主张必须保留原意。

展示文案包含 Hero Message、Supporting Message、Proof、Benefits、CTA 和按阅读区分配的 Display Copy。它可合并重复句、调整顺序与压缩说明，但每一句都能追溯到原文。封面只保留一个项目/活动语境眉题；主标题给出核心主张，副标题只补充新信息。语义重复与金色关键词的准确性写入 Plan 并交人类复核。给用户只展示项目、主标题、副标题、重点内容、行动信息和素材询问句。

## 3. 阅读区签名与节奏

每个阅读区记录：

```text
reader_question：读者此刻需要确认什么
claim：本段建立的结论
evidence_role：解释文字 / 事实或数据 / 真实资产 / 语义主视觉 / 程序化结构 / 行动引导
visual_relation：文字、主体、证据或结构如何共同解释 claim
Lxx / variant：由真实关系选择
intrinsic_height：正式字体和内容决定的高度
transition_to_next：下一段继续回答什么
rhythm_change：与相邻模块不同的结构骨架、图文关系、轨道或章节导航
```

阅读区是连续画布中的内容段，不是固定比例帧。相邻阅读区不得复用同一 `Lxx`，且必须有可感知的结构节奏变化；换颜色、翻转左右或换装饰不算变化。无真实结构时保留宽正文，而非伪造流程、图表、Logo 或箭头。

## 4. 图像、人物与二维码

首帧默认主题主视觉；中段图像只在解释本段关系时使用。AI 视频、AIGC 影像或 AI 创作活动的首帧应使用电脑、剪辑工作台、分镜、胶片或视频生成工作流等真实工具语义，不能用纯手工电影道具或泛科技装饰。ImageGen 不生成可读文字、数字、Logo、二维码、水印或真人身份。

导师人像只使用用户确认的原图；默认在中段与姓名、身份、履历组成同一信息组。二维码已上传即直接用于 CTA；用户明确没有二维码时写“待提供二维码”，使用占位并标记发布阻塞，不再开启确认轮次。
