```text
□ source_copy、fact_locks、display_copy 来源映射和本轮确认/素材记录均可追溯

□ final.png 由同一 poster.html 经 Playwright Chromium 导出，宽 1080px
□ 解释性正文为 Regular；模块/章节标签、日期、价格、行动和关键数据为 Medium 或更高
□ 浏览器实测字号、换行、溢出、容器内边距、CTA 与章节碰撞均通过
```

## B. 结构、首帧与主题

```text
□ 阅读区连续，无独立背景、暗带或拼接边界；内容多时扩高、拆区或重组
□ 相邻模块的契约、图文关系、轨道/结构线或章节导航有明确节奏变化；没有连续重复的左标签 + 左标题 + 列表
□ 首帧是无章节号封面；首帧后的第一个内容大模块为 01，后续章节连续递增。每个非首帧大模块的右侧低对比章节号均为 right=92px ±8px、顶部对齐眉题/章节标签、不压标题或正文且大于内部序号
□ 首帧顶部只有一个活动/项目语境眉题；副标题补充新信息，未复述眉题或主标题（human-review-needed）
□ 主标题金色关键词逐项来自原文并在 Plan 写出原文依据；额外金色仅用于结论、行动、关键产出或关键事实，解释正文不大面积染金（语义准确性为 human-review-needed）
□ 流程、课程安排或阶段路径的关键产出及结果内容已用主题金色明确高亮（如适用）
□ 首帧标题第一、主视觉第二且唯一；`data-hero-surface` 横向到达两侧，标题与视觉之间无无意义大空场；顶部融入、底部渐隐，无透明抠图感、图片卡、横向切线或矩形边界（融合质量为 human-review-needed）
□ 通栏主标题、副标题与说明共享已声明文本轴的左右边界；章节号、轨道和装饰没有使文本轴提前缩窄；必要文字已做章节碰撞保护
□ 首帧亮度、饱和度、暖黄克制；AI 视频/AIGC 主题具有真实工具语义；没有生成式文字、数字、Logo、二维码或水印
□ 主视觉 bbox、文案锚点、背景采样、接缝和 CTA 数据组由 Chromium 实测，Manifest 与当前 poster.html SHA256 一致
```

## C. 修复决策

- 客观错误、溢出、接缝、主体裁切、二维码、章节碰撞或自包含 HTML 失败：修复后重新打包、渲染和验收。
- 主视觉语义、材质、透视、视觉重量或品牌气质无法可靠判断：写 `human-review-needed`。
- 默认只允许针对命名失败项进行一次修复性完整导出。文字可读性以字号、换行、溢出和碰撞规则验收，不设置主观手机比例检查。
