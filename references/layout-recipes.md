# 长图信息结构配方

配方只定义内容关系、阅读次序与跨帧节奏；不规定主题颜色、主视觉资产、字体或卡片外观。黑金视觉决定见 `black-gold-system.md`，尺寸与对齐见 `layout-rules.md`。

先阅读本文件的“配方选择索引”，再从候选中选择主配方与阅读区契约。确认 `Lxx` 后才读取 `layout-contracts.md` 中对应的详细合同。R 配方决定整篇内容的推进关系，L 契约决定标题、正文、图像、步骤或行动信息的具体落位；二者不能互相替代。

先从文案的主关系选择一个**主配方**。需要时可以在其中嵌入一个局部结构（例如在 R1 的第二帧使用数据组），但不得把多个配方机械串接成“每帧一张独立海报”。

## 0. 选择方法

| 文案的核心关系 | 优先配方 | 不应误用为 |
|---|---|---|
| 一个主张，需要解释其内容、价值与加入方式 | R1 建立 → 展开 → 收束 | 四张等权信息卡 |
| 一个判断，需要用事实、案例或数据支撑 | R2 观点 → 证据 → 结论 | 只放抽象主视觉的宣传图 |
| 一个问题，提供若干方向或选择 | R3 问题 → 并列答案 → 行动 | 把所有并列项挤成小字清单 |
| 过程、教程、转化路径或步骤依赖 | R4 流程 → 阶段 → 结果 | 按内容长度随意切帧 |
| 需要并列比较两个至四个对象 | R5 比较 → 判断 → 行动 | 把比较表做成不可读的缩略图 |
| 课程、方案或项目包含多种关系（权益、阶段、日程、去向等） | R6 结构化信息展开 | 把所有模块平铺成同一种卡片 |

- 帧数由文案密度和每个模块的可读长度决定；配方中的 `V1 / V2 / V3` 只是最小阅读骨架。
- 默认使用 `N × 9:16`。横向截图、表格或并排比较本身是主要证据时，项目开始时整体选择 `N × 3:4`。
- 每个项目的具体分配必须写进 `plan.md` 的“整图节奏矩阵”；不能直接套用本文件的帧数。

## 0.1 配方选择索引（每案必读）

先判断真实信息关系，再登记“主候选 / 备选 / 未选原因”。日期词本身不自动等于时间轴；平级条目也不能被伪造成阶段或流程。

| 真实信息关系 | 必须评估的 L 契约 | 不适用时 |
|---|---|---|
| 核心承诺、标题、语境 | `L01 封面主张` / `L02 核心陈述` | 不把多项交付挤入首屏 |
| 正好 3 / 4 / 6 项平级解释 | `L03` / `L04` / `L12` | 项数或深度不一致时分组或扩高 |
| 权益、交付、价值、可选价格 | `L14 权益 / 价值清单` | 不因数量相同退化为普通网格 |
| 日期、周次、课次、真实先后 | `L15 时间轴 / 日程` | 无真实顺序时使用并列或正文结构 |
| 从基础到进阶的能力、课程、项目路径 | `L16 阶段路径` | 有日期但无进阶关系时用 `L15` |
| 两至四个对象的同维度比较 | `L05 双轨对照` | 不是比较证据时不强行对照 |
| 连续动作、过程或操作步骤 | `L06 纵向过程` | 没有依赖顺序时不画箭头 |
| 核心/外围、支持层、资源流向 | `L08 层级 / 关系图` | 无关系时不可制造节点图 |
| 单一真实案例、截图或材料解释 | `L09 图文解读` | 无证据图时不生成伪证据 |
| 同一现场的多张真实照片 | `L11 现场证据组` | 不能成为无叙事图库 |
| 人物身份、履历与真实头像 | `L13 人物信息墙` | 单人信息可用图文解读 |
| 真实机构、客户、去向或标识覆盖 | `L17 标识 / 去向矩阵` | 无真实标识不得生成 Logo |
| 价格、报名、二维码、下一步 | `L10 收束行动` | 不在解释段提前重复行动 |

结构判断完成后，Plan 才可标记 `approved-for-production`。相邻阅读区不能使用同一 `Lxx`，任一 `Lxx` 全图最多两次；当真实同类内容超过该用量或单区容量时，按 `layout-contracts.md` 的“同类内容过量时的合法处理”执行，不得缩字或伪造关系。

## R1 · 建立 → 展开 → 收束

适用：一个明确主张，配两到四个解释点、权益或行动信息。

```text
V1  主张 + 语境 + 内容相关主视觉
V2  两组解释 / 数据 / 证据
V3  权益、覆盖范围、价格与行动
```

节奏：首帧建立最高识别点；中段把“为什么值得看”说清；末段压缩为明确收益与行动。中段可以延展为两帧，但收束信息不得提前被重复。

不适用：需要完整流程教学或多案例对照的长文案。

## R2 · 观点 → 证据 → 结论

适用：趋势、研究、判断或观点型内容。

```text
V1  观点与问题
V2  数据、案例或人物证据
V3  结论、带走内容或行动
```

证据必须有内容语义，不能以抽象装饰替代。

如果证据多于两组，先按论证链分组，再增加帧；不要让每个证据各自成为同样重的卡片。

## R3 · 问题 → 并列答案 → 行动

适用：清单、课程、活动、方法论或机会筛选。

```text
V1  提出问题 / 选择理由
V2  2–4 个并列答案或方向
V3  资源、行动与收束
```

并列项多于四项时，增加帧，不做密集小卡片墙。

并列项必须共享同一阅读轴和相近的信息深度；不能把标题、案例、权益、价格混称为“并列答案”。

## R4 · 流程 → 阶段 → 结果

适用：有明确时间顺序、步骤依赖或转化路径的内容。

```text
V1  起点与目标
V2…N 阶段、步骤或关键决策
最终帧 结果、资源或行动
```

流程编号、步骤名和说明必须共享稳定阅读轴。

每一阶段只保留一个动作和一个结果；复杂条件移入说明文字或增加帧，不用箭头堆叠模拟流程。

## R5 · 比较 → 判断 → 行动

适用：选型、方案比较、同一问题的不同路径，且比较关系本身是内容证据。

```text
V1  比较对象、判断标准与阅读问题
V2…N  按同一维度展开差异 / 证据
最终帧  判断结论、适用边界与行动
```

- 每一比较维度只出现一次；所有对象采用同一对比顺序。
- 横向比较在手机端无法保持可读时，改为纵向分段；只有横向证据不可替代时才选择 `3:4`。

## R6 · 结构化信息展开

适用：课程简介、服务方案、训练营、项目说明等包含至少三种不同信息关系的文案。关系可为权益包、时间／阶段、能力路径、去向／标识矩阵、案例证据或行动，不把它们降格为一长串等权段落。

```text
V1      核心承诺 + 语境 + 语义主视觉
V2…N-1  按文案关系选择 2–4 种结构化阅读区
最终帧  结论、价格 / 行动与收束
```

- 先给每一组重复信息命名关系：`权益 / 日期 / 阶段 / 对照 / 证据 / 去向`。出现日期与先后时优先时间轴；出现价值、交付与价格时优先权益清单；出现阶段能力时优先阶段路径；出现真实机构或去向标识时优先矩阵。
- 同一长图的相邻阅读区不得使用同一 `Lxx` 契约；任一 `Lxx` 契约整张图最多使用两次。需要重复同类内容时，先按 `layout-contracts.md` 的合法处理顺序合并、使用已登记的同关系扩展变体，或在确有第二层真实关系时改路由；不得只换颜色或装饰后把同一配方连用。
- 结构化不等于制造图表：关系不成立时保留正文阅读区；没有真实标识资产时不生成品牌 Logo；没有时间顺序时不画时间轴。

## 配方交付最低要求

写完 Plan 后，以下内容必须明确，才能进入视觉生产：

```text
□ 主配方与选择原因
□ 每帧唯一内容任务
□ 首帧的阅读承诺
□ 中段的解释 / 证据关系
□ 末帧的收束与行动信息
□ 每个帧边界的缓冲策略
```
