# 人像首帧契约 P01–P04

仅在用户明确要求人物作为首帧主视觉、`portrait_hero_decision=mentor-portrait-by-request` 时读取。它扩展 `L01 封面主张`，不替代正文中的 `L13 人物信息`。

## 1. 配方路由

| 配方 | 人物数 | 关系 | 固定结构 |
|---|---:|---|---|
| `P01` | 人物数：`3` | 三人并列、中心聚焦 | 三颗头等尺度；中间人物在最前层，两侧人物在后层 |
| `P02` | 人物数：`1` | 单人焦点 | 人物放大至腹部附近；说明位于头部右侧安静区 |
| `P03` | 人物数：`2` | 双人等权 | 两颗头等尺度；同一露出比例；说明统一置于人物下方 |
| `P04` | 人物数：`4` | 四人两层分组 | 上层两人在后、下层两人在前；形成紧凑连续体量 |

人数与关系必须同时匹配。主次双人或超过四人不是已冻结配方，先停在 `human-review-needed`，不得伪装成 P01–P04。

## 2. 首帧共同关系

- 画布宽 `1080px`；人物、逐人说明和主标题共同使用 `x=112–968` 主内容轴。
- 眉题小且独立置顶；眉题与标题距离大于标题与副标题距离。主标题和副标题是一个近邻信息组，整体向下建立稳定阅读重心。
- 标题先读、人物后读。人物组和逐人说明共同组成主视觉，不能把人物排好后再补浮动标签。
- 人物组整体居中，水平中心相对画布中心误差不超过 `24px`；多人组左右可见轮廓与主内容区建立边界关系。
- 人物后方的抽象背景是连续 `[data-hero-surface]`，向人物上方和下缘之后延展，不裁成矩形卡片，不与人物在同一水平线结束。
- 背景可由 ImageGen 生成；人物不得由 ImageGen 改脸、重绘、扩图或重生。

## 3. 人像资产与下缘融合

- 真人与卡通均使用可复现的非生成式透明分割；排版只能引用已冻结 alpha，不得在不同配方中临时更换模型或退回原图矩形。
- 每张资产登记源图 hash、透明图 hash、分割模型/版本和 `asset-qa.json`。在 `#10100F` 与 `#F0ECE2` 两种底色上检查白边、灰边、源背景残留、发丝、眼镜、耳部、手指和衣物边缘。
- 已知纯色背景造成半透明边缘污染时，可使用 `scripts/decontaminate_alpha_edges.py` 去除边缘底色；它只校正半透明像素的 RGB，必须完整保留上游分割得到的 alpha，不得借机腐蚀、裁切或重画人物。
- 头顶、脸、下巴、肩部、手臂、手及源图中原本完整的部位不得被切掉。发现连续白边、原图矩形、硬切或缺失部位时，资产状态为 `blocked`。
- 唯一允许的人物融合模式是 `lower-fade-only`。肩部和主要躯干先保持实体，渐隐只发生在身体最下缘；过渡长度不少于 `240px`。
- 渐隐终点必须在源图真实 alpha/画面边界之前完全透明，不得露出底边、手臂平口或水平切线。完整肢体优先于统一底线。

## 4. 通用人物映射

- 多人按最终可见 `head_bbox` 排版，不按源图宽高、焦段或留白排版。P01/P03 头部高度差不超过 `3%`；P04 不超过 `max(4%, 8px)`。
- P01/P03 的头部框不得相交。P04 允许头发外框接触，但 `face_bbox` 不得相交；脸、五官和眼镜永不遮挡。
- 身体交叠只发生在肩部以下，任意两人的身体交叠不超过较小一方可见身体面积的 `1/3`。
- 人数减少时必须放大人物；人数增加时建立前后层级与连续体量，不能缩成零散头像。
- 每位人物有且只有一个“姓名 + 身份”说明组。同一张海报内，全部人物说明使用相同对齐、字号、间距和基线逻辑。
- 姓名使用主题金 `#CCAA77` 或主题金标签；身份说明使用暖白/暖灰。文字不得遮脸、五官、关键手势，也不得让读者猜测归属。

## 5. 配方细则

### `P02` 单人焦点

- 人物从头部完整露出到腹部附近，肩部和躯干实体后再渐隐。
- 人物肩部可见宽度与主标题实测宽度误差不超过 `5%`，且不越过 `x=112–968`。
- 姓名和身份放在人物头部右侧，并与头部形成一个信息组；不得压脸。

### `P03` 双人等权

- 两人头部等尺度，眼线和露出比例接近；可见轮廓整体居中并接近内容区左右边界。
- 默认不发生身体交叠；素材姿态造成的轻微交叠仍不得遮肩线或超过 `1/3`。
- 两组说明位于人物下方，使用完全相同的对齐方式、字号、间距和顶部基线；已验收基线为居中对齐。

### `P01` 三人并列

- 三颗头等尺度，身体露出终点一致，人物组形成横向矩形体量。
- 中间人物在最前层并成为焦点；焦点来自层级，不来自放大头部。
- 三组说明位于人物下方，共用同一基线、对齐方式和层级。

### `P04` 四人两层分组

- 上层两人在后，下层两人在前，按左右两列斜向交错。四颗头保持近似等尺度。
- 后排每人至少完整露出头部、颈部、双肩和一段实体躯干；前排不得遮住后排肩线。
- 前后两层组内密度接近；如果前排已经交叠，后排人物之间不得留下明显更大的空洞。
- 四人共同形成紧凑菱形或横向矩形体量，组宽不小于主内容宽度的 `82%`。
- 左侧人物标签置于外侧左方，右侧人物标签置于外侧右方；前排说明优先置于肩部外侧，但所有文字仍在 `x=112–968`。
- 姓名使用金色直角矩形标签，标签顶部与身份说明首行顶部误差不超过 `4px`。
- 竖排说明中的数字、英文及中英混合词用单一横排 token，例如 `AI`、`12`、`B端`；禁止逐字符拆开。

## 6. HTML 与 Manifest

所有配方统一使用：

```html
<div data-hero="portrait-ensemble" data-portrait-recipe="P04" data-hero-ensemble>
  <figure data-hero-subject="wizard" data-depth="foreground" data-z-index="4">
    <span data-hero-head></span>
    <span data-hero-face></span>
    <span data-hero-shoulder-visible></span>
    <figcaption
      data-hero-subject-caption
      data-caption-alignment="top"
      data-caption-orientation="vertical"
      data-required-protected-tokens="AI|12|B端">
      <span data-hero-subject-label>姓名</span>
      <span data-hero-subject-role><span data-no-split-token>AI</span> 工作坊</span>
    </figcaption>
  </figure>
</div>
```

- 正式 Manifest 为 `yinxi-layout-manifest-v4`；`recipe_id` 必须为 P01–P04，人物数分别为 `3 / 1 / 2 / 4`。
- 每人实测 `head_bbox`、`face_bbox`、`shoulder_bbox`、`visible_bbox`、`body_visible_bbox`、`caption_bbox`、`label_bbox`、`role_bbox`、深度、z-index 与保护 token。
- 几何只能由最终 `poster.html` 的 Chromium DOM 导出，不得手填 Manifest。
- 修改 HTML 后必须重新打包、测量、渲染和验证；只修改 PNG 不算完成。

## 7. 自动与人工验收

自动硬校验人物数、内容边界、整体居中、头部尺度、脸部相交、身体交叠、前后层级、肩部实体、说明对齐、标签顶对齐、保护 token、文件 hash 与同源渲染。

以下仍须人工查看完整 PNG 和命中风险区：真人/卡通边缘污染、不同焦段的视觉重量、P04 前后层密度、下缘是否自然、背景是否成熟连续、姓名与人物归属是否一眼明确。自动通过只能写 `agent-checked / human-review-needed`；用户明确确认后才写 `human-approved`。
