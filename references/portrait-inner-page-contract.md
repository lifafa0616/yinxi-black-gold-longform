# 人像内页契约 IP01–IP04

仅用于首帧之后的 `L13 人物 / 导师信息` 阅读区。它把人物与配套文字组织成正文信息模块，不承担封面主视觉；正文人物不得调用 P01–P04，首帧人物也不得调用 IP01–IP04。

## 1. 配方路由

先按人物数量、逐人文案密度和阅读关系选择配方，不能只按“有几张照片”选择。

| 配方 | 适用输入 | 固定信息关系 | 状态 |
|---|---|---|---|
| `IP01` | 2 人；每人有姓名、身份和 1–3 行说明 | 双人交替信息卡：两张横向卡上下排列，人物与文字左右交替 | 已验证 |
| `IP02` | 3 人；每人有姓名、身份和 1–3 行说明 | 三人资料列表：三行重复的“人像 + 资料”结构 | 已验证 |
| `IP03` | 4–8 人；每人只有姓名和短身份 | 紧凑头像网格：等尺寸头像与下方短说明形成名册 | Figma 提取，正式使用后仍需人工确认 |
| `IP04` | 4 人；每人有姓名和短身份，可有一句短说明 | 四人独立容器阵列：四个高低有节奏但底部对齐的独立人物容器 | 已验证 |

- 信息超过配方容量时，增加 `L13` 阅读区或改用已验证的 `L13-M04-3C`；不得缩小人物、姓名或正文来硬塞。
- 单人内页仍使用 `L13` 的单人图文关系，尚未冻结为 IP 配方；不得借用首帧 `P02`。
- 需要突出主讲或人物之间存在主次关系时，先在 Plan 写明层级；IP01、IP02、IP04 的默认语义是同级人物。

## 2. 与首帧的硬边界

- IP 模块必须位于首帧之后的 `[data-major-module]`，所在阅读区必须是 `data-contract="L13"`，并保留正文章节号。
- IP 模块不得包含 `data-hero-cover`、`data-hero-surface`、`data-hero="portrait-ensemble"` 或 `data-portrait-recipe="Pxx"`。
- 内页标题、引导语先建立本节问题，人物模块随后回答；不得照搬首帧的“眉题 + 超大主标题 + 整组人物主视觉”结构。
- 人像宽度服从当前正文内容轴，默认不超过 `x=112–968`。人物可以在自己的容器内溢出，但整个模块、姓名和说明不得越过内容边界。
- IP 配方只决定人物信息模块；整篇仍由 R 配方和 `L13` 决定阅读区在长图中的位置与前后关系。

## 3. 通用人物—文字关系

- 人物与配套文字属于同一信息单元。每位人物必须有唯一 `unit_id`，姓名、身份和说明不能漂到相邻人物区域。
- 同一模块内，姓名、身份和说明采用同一字号体系、间距逻辑与文字对齐方式；不能一个左对齐、另一个居中。
- 姓名是逐人说明的第一视觉点，使用主题金 `#CCAA77` 或主题金标签；身份和说明使用暖白 / 暖灰。标签存在时，标签顶部与同组文字顶部对齐 `±4px`。
- 多人按最终可见的头部视觉面积校准，不按源图尺寸、焦段或画布留白校准。同一模块头部高度差默认不超过 `5%`；IP03 不超过 `4%`。
- 人物露出比例按配方统一。透明半身像至少完整露出头、颈、双肩和一段实体躯干；人数减少时放大人物，使模块饱满，但不得越过内容区。
- 头顶、脸、下巴、肩部、手臂、手及源图中本来完整的部位不得硬切。透明人像只允许在身体最下缘使用 `lower-fade-only`；实体躯干优先，渐隐不得提前吞掉肩部或主要身体。
- 人物之间默认不互相遮挡。确需轻微交叠时，脸和五官不得遮挡，身体交叠不得超过较小一方可见身体面积的 `1/3`。
- 真人与卡通沿用同一套非生成式透明分割、边缘去污染和双底色 QA；不得为某个内页配方临时退回带原背景的矩形图。

## 4. 黑金内页视觉 Token

以下数值以 `1080px` 母版和默认安全轴 `x=112–968` 为基准；降低全局边距时按 `layout-rules.md` 同步重算。

```text
module width             856px
title → portrait module   64–96px
module outer gap          48–96px
gold                     #CCAA77
primary text             #F0ECE2
secondary text           rgba(240,236,226,.64–.76)
hairline                  rgba(204,170,119,.28–.46)
panel fill                rgba(240,236,226,.025–.055)
panel radius              24–32px（IP01）；IP04 可使用拱形顶
name size                 34–44px
role size                 24–30px
bio size                  24–28px
```

- 只允许低对比金线、暗金光晕或与整图连续的抽象背景辅助分组；不能把每个人做成独立发光海报。
- 内页视觉焦点仍是本节结论与人物证据的关系。人物不能压过整张长图的首帧标题层级。

## 5. 配方细则

### `IP01` 双人交替信息卡

- 两张卡片上下排列，外边缘共同对齐内容轴；卡高按文案自适应，建议 `320–420px`，卡间距 `72–96px`。
- 第一张“人物左 / 文字右”，第二张“文字左 / 人物右”；交替的是图文位置，不是文字对齐，两个文字组默认都左对齐。
- 人物占卡宽约 `36–44%`，可从卡片上缘溢出 `32–72px`；头部、双肩和主要躯干保持实体，渐隐只在卡片下缘附近完成。
- 文字完全位于人物对侧的安静区；姓名、身份、说明从上到下组成一个紧邻组，不把说明压在身体上。

### `IP02` 三人资料列表

- 三个条目使用同一人像列、同一文字列和同一行高逻辑；推荐人像列宽 `208–256px`，列间距 `48–64px`。
- 三张人像使用相同形状、同一头部尺度和同一露出比例。透明半身像与蒙版头像不得在同一列表混用。
- 姓名、身份和说明全部左对齐，并在三行中保持相同起始轴；条目之间用 `40–64px` 留白或一条低对比分隔线。
- 列表按从上到下阅读，不通过前后遮挡制造层级。

### `IP03` 紧凑头像网格

- 只适用于 4–8 位人物的短名册；每人最多“姓名 + 两行短身份”，长简介改用 IP02 或拆分阅读区。
- 使用 2–4 列等宽单元；头像形状、直径、头部面积和下方说明间距完全一致，最后不足整行时整行居中。
- 姓名和身份置于头像下方并统一居中；人物单元之间不得交叠，也不得用不同大小突出个别人。
- 使用蒙版时逐张声明裁切锚点，完整保留头顶、脸和下巴；使用透明头像时不得残留原图白底或灰边。

### `IP04` 四人独立容器阵列

- 四个容器共同占满内容轴，列宽一致、底部对齐；容器高度可形成轻微节奏，但最高与最低差不超过 `96px`。
- 每人只属于一个容器。姓名和身份位于容器顶部，人物位于其下；四组文字使用同一顶部基线、对齐和间距逻辑。
- 人像按头部面积统一，肩部与实体躯干优先。容器可在最下缘接收渐隐，但不得裁掉原本完整的手臂或制造水平硬切线。
- 容器之间保持 `16–24px` 净距；人物轮廓不得跨容器遮挡相邻人物或文字。
- 四个容器作为一组在内容区居中，左右外边缘分别与 `x=112`、`x=968` 对齐，不能缩成画面中间的一排小头像。

## 6. HTML 与 Manifest

```html
<section data-reading-zone="speakers" data-contract="L13" data-major-module="speakers">
  <div data-inner-portrait-recipe="IP01">
    <article data-portrait="transparent" data-portrait-unit="speaker-a" data-portrait-side="left">
      <div data-portrait-related-text-region>
        <img data-portrait-subject alt="" />
        <div data-portrait-intro>姓名与身份</div>
      </div>
    </article>
  </div>
</section>
```

- 配方根节点使用 `data-inner-portrait-recipe="IP01|IP02|IP03|IP04"`；每位人物使用唯一 `data-portrait-unit`。
- `export_layout_manifest.py` 为每位正文人物记录 `inner_recipe_id`、`unit_id`、`reading_zone_contract`、`is_in_hero_cover` 和 `caption_alignment`，同时保留原有 `portrait_mode` 与几何字段。
- `verify-case-layout.py` 校验 IP 命名空间、人数、`L13` 所属、不得进入首帧、逐人 ID 唯一及同组文字对齐一致；图像边缘、视觉重量、容器节奏和人物—文字归属仍为 `human-review-needed`。

## 7. 验收顺序

1. 先单独检查透明资产：白边、灰边、残留背景、完整部位和下缘渐隐。
2. 再检查逐人单元：头部尺度、露出比例、姓名归属和文字对齐。
3. 再检查整个 IP 模块：内容轴、饱满度、模块居中和与标题区的距离。
4. 最后放回完整长图检查：它是正文证据，不应看起来像第二张封面。
