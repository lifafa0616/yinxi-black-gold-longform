# 长图生产流程

唯一生产链为 `1080px 连续 render.html → 中间 poster.html → 同一 Chromium 导出 final.png`。`final.png` 是唯一正式发布物；阅读区不是固定比例帧。

## 1. 确认与素材收集

保存 `source_copy`、`current_input_allowlist` 与全部 `fact_locks`。只使用当前对话明确提供的素材；基线样张只校准质量，不是素材。

先输出展示文案确认稿：项目、主标题、副标题、重点内容、报名/行动信息，随后原样附加 `content-planning.md` 中的“这张长图的开头第一屏，你希望读者第一眼先记住什么？”三选一和素材上传说明。它们属于同一轮文案确认，不增加新的确认轮次。

用户确认并上传后，将第一屏选择、人像和二维码登记到 Plan 与白名单。不得重复索取已提供素材。用户要求修改文案时，只修订确认稿并保留或重新确认受影响的第一屏选择，不启动生产。

内部映射固定为：选项 1：`theme-imagegen`；选项 2：`mentor-portrait-by-request`；选项 3 由 Agent 判断。只有人物是核心卖点、已有清晰原图且人数与关系可用时，选项 3 才进入人像开场；没有足够依据或用户未选择时，使用选项 1。二维码已上传即进入 CTA；明确没有时做“待提供二维码”占位，并把发布状态标为待补输入。

命中 `mentor-portrait-by-request` 后读取 `portrait-first-frame-contract.md`：按人数与真实关系登记 `portrait_recipe=P01|P02|P03|P04`，先完成非生成式透明资产及双底色边缘 QA，再进入排版。未命中已冻结配方时不得自行发明 P 编号或退回原图矩形裁切。

## 2. 结构与首帧

选择一个 R 配方和各阅读区的 L 契约，按真实关系而非组件库存决定。相邻模块必须在契约、图文关系、轨道/结构线或章节导航上有结构节奏变化；不能重复平铺“左标签 + 左标题 + 列表”。

第一屏按已记录的 `portrait_hero_decision` 使用内容主题画面或导师/嘉宾人像。首帧作为无章节号封面，唯一眉题给出项目/活动语境，标题第一、主视觉第二。`data-hero-surface` 从中下部横向满幅融入母版，内含唯一主视觉；首个内容大模块才从 `01` 开始。内容主题画面局部验收检查顶部融合、底部融合、标题优先、无无意义大空场、亮度/饱和度/暖黄克制、语义相关、真实工具语义（AI 创作题材）及无生成式文字。人像首帧还必须检查头部视觉尺度、肩部与肢体完整、身体实体比例、遮挡上限、统一说明关系及 `lower-fade-only`；人物绝不由 ImageGen 改脸或重生。

## 3. 渲染与客观检查

1. 用 `render.html` 建立连续画布；解释正文用 Regular，日期、价格、行动、关键数据和标签用 Medium 或更高。
2. `package_poster_html.py` 将本地图片和 CSS 图片资源打包进 `poster.html`，并接入批准的 Google Fonts `Noto Serif SC 700` 与 `Noto Sans SC 400/500`。
3. `export_layout_manifest.py` 从 Chromium 取得换行、容器、首帧、CTA、章节导航与碰撞数据；不得手填。
4. `render_longform.py` 先确认三种 Google 字重真实加载，再从该 `poster.html` 导出 `final.png`；`verify-case-layout.py` 重新测量并验证。联网失败不得回退系统字体。

超长图只允许同一 Chromium 的像素条带拼接。验收看完整 PNG 和命中风险区裁片；文字由字号、换行、溢出和碰撞规则保障，不另设主观手机比例检查。
