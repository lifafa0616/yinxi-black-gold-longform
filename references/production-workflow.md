# 长图生产流程

唯一生产真源为 `1080px 连续 HTML → 自包含 poster.html → 同一 Chromium 导出 final.png`。阅读区不是固定比例帧。

## 1. 确认与素材收集

保存 `source_copy`、`current_input_allowlist` 与全部 `fact_locks`。只使用当前对话明确提供的素材；基线样张只校准质量，不是素材。

先输出展示文案确认稿：项目、主标题、副标题、重点内容、报名/行动信息，随后原样附加：

> 是否有希望使用的导师/嘉宾人像，以及报名二维码可一并上传？如有，请现在一并提供。

用户确认并上传后，将人像和二维码登记到 Plan 与白名单。不得再问“是否把人像放在首帧”，也不得重复索取二维码。用户要求修改文案时，只修订确认稿，不启动生产。

`portrait_hero_decision` 默认 `theme-imagegen`：人像用于中段讲师信息。仅用户明确要求人像作为首帧主视觉时使用 `mentor-portrait-by-request`。二维码已上传即进入 CTA；明确没有时做“待提供二维码”占位，并把发布状态标为待补输入，不为此开启新确认轮。

## 2. 结构与首帧

选择一个 R 配方和各阅读区的 L 契约，按真实关系而非组件库存决定。相邻模块必须在契约、图文关系、轨道/结构线或章节导航上有结构节奏变化；不能重复平铺“左标签 + 左标题 + 列表”。

默认首帧使用主题主视觉：首帧作为无章节号封面，唯一眉题给出项目/活动语境，标题第一、主视觉第二。`data-hero-surface` 从中下部横向满幅融入母版，内含唯一主视觉；首个内容大模块才从 `01` 开始。局部验收检查顶部融合、底部融合、标题优先、无无意义大空场、亮度/饱和度/暖黄克制、语义相关、真实工具语义（AI 创作题材）及无生成式文字。人像绝不由 ImageGen 改脸或重生。

## 3. 渲染与客观检查

1. 用 `render.html` 建立连续画布；解释正文用 Regular，日期、价格、行动、关键数据和标签用 Medium 或更高。
2. `package_poster_html.py` 将图片、CSS 资源、Serif Bold、Sans Regular、Sans Medium 打包进 `poster.html`。
3. `export_layout_manifest.py` 从 Chromium 取得换行、容器、首帧、CTA、章节导航与碰撞数据；不得手填。
4. `render_longform.py` 从该 `poster.html` 导出 `final.png`；`verify-case-layout.py` 重新测量并验证。

超长图只允许同一 Chromium 的像素条带拼接。验收看完整 PNG 和命中风险区裁片；文字由字号、换行、溢出和碰撞规则保障，不另设主观手机比例检查。
